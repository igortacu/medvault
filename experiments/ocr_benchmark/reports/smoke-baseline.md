# Tesseract smoke baseline

Executed locally on macOS arm64, 16 GiB system RAM, Python 3.11.15,
Tesseract 5.5.1, two persistent protocol workers. This is a synthetic smoke test,
not a model selection report. 15 pages, 3 source-document clusters, 2 repetitions.
Font: system Arial; raster inputs generated by generate_smoke.py.

| Metric | Observed |
|---|---:|
| Completed | 30/30 |
| CER micro | 0.8383% |
| WER micro | 4.5833% |
| Token omission micro | 0.0000% |
| Failure rate | 0.0000% |
| Request p50 | 220.2 ms |
| Request p95 | 399.0 ms |
| Sampled worker-tree RSS peak | 95.7 MiB |
| Executed requests / wall second | 7.47 |

The English-only exploratory configuration had CER 17.60% and WER 28.33% on
this same multilingual template set. Those are intentionally mismatched language
settings, not evidence that Tesseract is unsuitable for Russian or Romanian.

No annotated table/formula/field extraction cases exist in this smoke corpus:
TEDS, CDM, field F1 and semantic similarity are **not measured**. Metric contracts
are tested separately. Six hidden-marker attempts (3 languages x 2 repetitions)
produced zero observed markers; external actions were not instrumented, and this
is not evidence of general prompt-injection resistance.

Run identity and all configuration/checksums: tesseract-smoke-summary.json.
Raw synthetic predictions and SQLite checkpoints remain in ignored local artifacts/.

Host load was not controlled; the final Tesseract run overlapped Paddle inference.
Latency is exploratory, not a fair dedicated-hardware throughput comparison.
